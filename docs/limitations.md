# Limitations and operational boundaries

This project has local tests and microbenchmarks, not production adoption evidence.

Source-of-truth semantics belong to the loader. Replicas, eventual consistency, nondeterministic data, time-dependent fields and authorization context can change the apparent result. Sampling estimates selected cache-hit disagreement, not all historical staleness. Hot keys receive deterministic window decisions and cooldowns, so results are not an unbiased census of requests or unique keys.

Two-read filtering reduces false positives but cannot prove linearizability. Cache and origin reads are not atomic. ABA changes can evade the filter; an intervening write can still cause a stale classification. A mismatch incurs two origin calls and one additional cache read; age measurement adds PTTL plus an initial verification GET. PTTL-derived age assumes the configured TTL was originally applied and has not been extended. It is not an exact insertion age.

All scheduling limits are per auditor, per process. Multiple instances multiply load. Default burst is 20 verifications and refill is 20/second, potentially 40 loader calls/second under sustained mismatches. Token buckets bound long-run rate, not every sliding one-second window. Pausing stops new work; admitted jobs continue. Queue rejection consumes cooldown. Capacity eviction can permit earlier rechecks.

Asynchronous deadlines do not kill underlying promises. Each loader/read/callback class has at most maxConcurrent outstanding promises; exporter has one. Uncooperative operations can permanently occupy those slots. Such operations may retain keys/values through application closures until settlement. Active queue jobs necessarily hold original values transiently. Full values never enter aggregation/export records. Comparison, decoding, miss predicates and normalization are synchronous contracts. Accidentally returning a Promise disables further invocation of that function and consumes its rejection; checks fail safely. Async histogram hooks violate their synchronous contract, are counted and occupy at most one pending hook slot. The SDK cannot control what user loaders, callbacks, exporters or custom normalizers log independently.

Comparison accepts plain data, limits depth to 100 and counts canonical bytes including type tags. Sorting requires Object.keys allocation; a preexisting object with enormous key count still costs enumeration. Strings are size-checked before JSON escaping; escaping can allocate a bounded multiple of maxCompareBytes. Buffer encoding is bounded before allocation. BigInt decimal conversion and malicious Proxy traps cannot be preempted. Custom comparison receives original values, must implement its own ignore semantics, and can violate equivalence relations. Mutating the original object between scheduling and verification can also affect generic adapters; Redis strings are immutable.

The request path does synchronous rule matching and SHA-256 sampling. Pathological regexes, huge keys and high rule counts can increase latency. Heavy verification still shares Node's event loop. The benchmark is a mock, not a production latency claim.

Callback-style reads, pipelines, transactions, streams, Lua commands and client-returning method chains bypass interception. Only promise GET/MGET hits are audited. Users should configure separate auditors for independent origins because each auditor has one breaker. A custom normalizer is a trust boundary; labels derived from sensitive values violate the privacy contract. Normalized rule templates can merge metrics from semantically different rules; regex numbering is local to each wrap call.

Metrics delivery is best effort. Export exceptions can lose a snapshot; no retry/replay occurs. A hanging exporter blocks subsequent exports while bounded counters keep accumulating. Final exporter/callback errors may lack a later successful export. OTel provider errors during asynchronous collection cannot be counted by the SDK. `exporter: false` uses bounded internal aggregation but emits nothing. JavaScript numeric counters can lose integer precision after extremely large totals. Shutdown deadlines assume the event loop remains responsive.

The Docker stack is development-only. No live Redis/PostgreSQL/Grafana services were available in the initial build environment; configuration checks and injected HTTP tests do not replace a live deployment smoke test. CI includes real Redis; run Compose locally before release. See the release checklist in CONTRIBUTING.md.
