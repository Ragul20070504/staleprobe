# Design decisions

- **Return the original hit, defer work.** A Proxy preserves client methods while a setImmediate queue avoids running loaders/comparison inline. An application can use the adapter contract without importing Redis. A separate cache implementation would duplicate application responsibilities.
- **Hash canonical typed tokens.** Streaming SHA-256 avoids retaining serialized payloads. Type tags avoid ambiguous JSON conversions for BigInt, Date, Buffer and non-finite numbers. JSON alone was rejected because it loses these distinctions. Depth/bytes/node limits bound ordinary traversal. Object key enumeration and synchronous user proxies remain limitations.
- **Bound slots beyond timeout.** Promise.race alone bounds response time but can create unlimited live origin calls. OperationGate retains its underlying slot until settlement; new calls skip when all slots are held. Workers can be released while origin load remains bounded. Worker threads could kill isolated pure computation but cannot safely move arbitrary application closures or clients.
- **Local token bucket.** It permits short bursts and caps starts without another runtime dependency. The budget counts verifications, so mismatch verification may double loader-call load. Distributed coordination is outside this SDK.
- **Rolling breaker.** Last 100 calls/60 seconds and ten-call minimum avoid lifetime-average dilution and tiny-sample decisions. A single recovery verification limits probes. A global auditor breaker may suppress healthy rules if one origin fails; separate auditors isolate sources.
- **Default labels derive from configured templates.** Regexes get numbered labels. Normalizing arbitrary keys heuristically can leak short user identifiers. Explicit trusted normalization remains available, with bounded cardinality. This is a deliberate privacy-first refinement of the original key-normalization requirement.
- **Exact live histograms, numeric snapshots.** The OTel API cannot ingest aggregate histogram buckets. Optional synchronous hooks record actual observations, while custom exporters receive exact compressed bins in interval snapshots. Reconstructing samples from buckets would distort distributions. SDK failures are counted; provider-internal async collection errors belong to the provider.
- **Cancel rather than drain on shutdown.** Draining a rate-limited queue could take minutes. Cancellation stops queued work immediately and aborts active operations. Final export deadlines bound waits for cooperative async work; no JavaScript API can put a deadline on a blocking synchronous function.
- **No exporter retries.** A custom exporter may partially commit before throwing, so replay risks duplicate counters. Failed snapshots are lost and errors counted when a later export succeeds. This is best-effort telemetry, not durable accounting.
- **Single package.** Native APIs handle scheduling and hashing. Optional ioredis is structurally typed, and only OTel API is mandatory at runtime. The example alone brings HTTP/database/metrics SDK dependencies.
